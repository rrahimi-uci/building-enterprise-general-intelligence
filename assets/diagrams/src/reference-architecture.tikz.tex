% Figure 4-1 -- The reference architecture as seven ownership planes.
% Restyled from reference-architecture.gv; every plane and chip of the original is kept.
% Layout: planes as rows of chips, the two cross-cutting planes as side rails, and a key
% beneath the figure that names the three line styles and expands every abbreviation.
%
%   planes (top to bottom): Experience and channels (with the dashed Edge and admission
%        sub-plane), Runtime and workflow, Knowledge, context, and memory, Agent applications,
%        Gateways and integration ("the only way out"), Systems of record and providers
%        ("outside the trust boundary")
%   Security and governance (left rail, red): IdP . STS, Workload identity, PDP / PEP,
%        Guardrails, Secrets . leases, Approval Service, Audit . WORM
%   Evaluation and operations (right rail, amber): OTel collector, Trace store, Evaluation
%        service, Datasets, SLOs . cost, Incident tooling, ReleaseManifest
%   request path (solid blue): API clients>API Gateway "Intent"; Request validator>Run API
%        "Admitted run"; Planner>Context Service "Assemble context"; Context Service>Bounded
%        agent workers "AgentStepRequest"; Bounded agent workers>Tool Gateway "Proposed action"
%        (the gateway checks it against policy before anything commits); Tool Gateway>Domain
%        systems "Committed effect"
%   control (dashed red, three): PDP / PEP > API Gateway (admission), > Run API (run control),
%        > the Gateways and integration plane (every gateway is an enforcement point)
%   evidence (dotted amber): every plane inside the trust boundary -- Request validator,
%        Workflow engine, Memory service, Topology . handoffs, Egress proxy -- joins one evidence
%        bus that ends at the OTel collector
