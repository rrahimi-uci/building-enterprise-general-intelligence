% Figure 8-1 -- Discovery proposes candidates; a requirement names one capability;
% resolution narrows its versions against the run envelope and pins one, or fails.
% Same lesson as the original skill-resolution figure, now worked through one
% Harborlight requirement so every step shows its input and its result.
%
%   DISCOVERY (cyan group): Capability need "read income evidence against policy"
%        -> Catalog search (semantic; lists only what the caller may see)
%        -> Candidates: mortgage.evidence.read 0.1.0 and 0.1.1, mortgage.income.verify 1.0.0
%   "Choose one capability" -> SkillRequirement: mortgage.evidence.read ^0.1, purpose, risk R1
%        (carried by the AgentSpec or the plan); red callout: the model may describe the
%        need but never sees unfiltered candidates or influences resolution
%   RESOLUTION (amber group): five filters in order, each with the versions it leaves --
%        1 capability and version range (0.1.0, 0.1.1); 2 release stage allows this run
%        (0.1.0; 0.1.1 is Staged for a canary this run is not in); 3 run envelope (0.1.0); 4 risk within ceiling (0.1.0);
%        5 health and cost (0.1.0). The run envelope (tenant, purpose, subject and
%        actor grants, data classes, region) feeds filter 3.
%        Decision "Any version left?": yes -> Pinned release (highest left, 0.1.0,
%        sha256:9f3c..., recorded in the RunManifest); no -> Refusal naming the filter
%        that emptied the set (dashed red)
%   After resolution: the pinned release is bound into the AgentStepRequest (tier-2
%        instructions, eligible tools, runtime bounds); every call it proposes still
%        passes the Tool Gateway -- resolution is not call authorization
