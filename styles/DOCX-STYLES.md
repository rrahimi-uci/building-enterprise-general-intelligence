# DOCX Style Specification

The executable source is `tools/build_book.py`; this file documents intended semantics.

| Style | Base | Semantics |
|---|---|---|
| Normal | built-in | body paragraphs |
| Title | built-in | title-page title only |
| Subtitle | built-in | subtitle/edition line |
| Heading 1–4 | built-in | chapter/appendix through local hierarchy |
| Caption | built-in | diagram/image caption |
| Book Part | custom | standalone Part divider title |
| Book Callout | custom | decision, rule, caution, implementation note |
| Book Evidence | custom | source-scope/evidence note |
| Book Reference | custom | hanging-indent bibliography entry |
| Book Code Label | custom | code language label |

Global rules:

- Do not apply direct formatting when a style can express the semantics.
- Heading styles keep with the next block.
- The first prose, list, or implementation-label block after an H2/H3 keeps
  with its following block when the reviewed publication uses that lead-in
  treatment.
- New-page behavior is generated from H1 semantics rather than manually inserted in DOCX.
- Headers/footers and page numbers are fields generated by the builder.
- Core metadata is fixed from `config/book.json`.
- Tables and code panels are styled programmatically because Word named styles do not fully encode cell-level rules.
- `templates/book-style-template.docx` is a visual/sample template, not the canonical content source.
