# Building an Enterprise General Intelligence Platform

**Book v1.0.0 development system**  
Author: **Reza Rahimi, PhD**  
Release date: 2026-09-13

This repository is both the publication release and the reproducible source system for future editions. A new maintainer should be able to edit, validate, rebuild, and package the book using only this repository.

One canonical source in `source/parts/*.md` produces three synchronized representations: **Markdown**, **DOCX**, and **XeLaTeX**. They are generated by the same assembler and are never edited independently.

## Canonical-source contract

1. **Edit:** `source/parts/*.md` in numeric order.
2. **Reference metadata:** edit `config/references.json`; cite sources as `[Rxx]` in prose.
3. **Assets:** add diagrams to `assets/diagrams/` and register them in `config/diagrams.json`.
4. **Assemble:** `tools/assemble_manuscript.py` generates `book/manuscript.md` and the distributable Markdown file.
5. **Render:** `tools/build_book.py` generates DOCX from the assembled manuscript and configuration.
6. **Validate before release:** never hand-edit generated DOCX or distributable Markdown.

`source/original/` is immutable provenance. `tools/prepare_manuscript.py` is the frozen one-time migration/bootstrap tool from the v3.1 draft. Never run it during ordinary editing: it would regenerate `source/parts` from the legacy source and undo the current v1.0.0 structure.

## Quick start

```bash
make setup      # .venv + Python dependencies + any missing TeX packages
make pdf        # validate the LaTeX source, then compile to dist/*-LaTeX.pdf
make help       # every available target, grouped by purpose
```

`make setup` is safe to re-run and installs TeX packages into your user tree, so
it never needs `sudo`. Once a `.venv/` exists, every `make` target uses it
automatically — there is no separate "activate the environment" step.

**Requirements**

| For | You need |
|---|---|
| Markdown + DOCX | Python 3.13 and `requirements.txt` (`python-docx`, Pillow, PyMuPDF, pdfplumber, fontTools) |
| XeLaTeX PDF | A TeX distribution with XeLaTeX. Full TeX Live works out of the box; BasicTeX/`texlive-base` needs `./tools/bootstrap_tex.sh`, which `make setup` runs for you |
| Pagination QA (`make qa-pdf`) | LibreOffice — optional |
| Cover/diagram regeneration | Microsoft core fonts or metric-compatible substitutes (Liberation Sans) |

No local TeX at all? `Dockerfile.latex` builds the PDF in a container, and CI
builds it on every push.

The release ZIP is written next to the repository root by default. All commands
derive paths from their script location and do not depend on `/data`.

## Runnable code examples

Every code listing in the book is the exact text of a file under `examples/`,
and CI executes it. Chapters cite an example by marker:

```markdown
[[EXAMPLE:mlflow-trace-configuration]]
```

`tools/assemble_manuscript.py` expands the marker at assembly time, so the
Markdown, DOCX, and XeLaTeX editions all carry identical, verified code and no
listing can drift from the file that CI runs. Agent examples execute offline
against a scripted model that implements the Agents SDK `Model` interface, so
they need no API key. See [examples/README.md](examples/README.md).

The cumulative mortgage implementation lives in `mortgage_case/`. Its current
foundation follows synthetic case `MORT-2026-000184` through checkpoints `C01`–
`C03`: read-only evidence summary, deterministic proposal validation, and the
provider-neutral runtime seam. It never approves or denies credit and never
writes to a real loan-origination system.

```bash
make examples        # validate the registry and every [[EXAMPLE:id]] marker
make examples-run    # execute the example test suite against the pinned SDKs
```

### Companion code correction notes

These notes record fixes made to the companion code before 1.0.0. They moved
here from Appendix I, which now covers only how to run and verify the code.

* SDK HITL returns a structured RunResult; it no longer throws serialized run state in an exception.
* The protected write tool is registered, and it carries an enterprise approval ID and proposal hash to the gateway.
* MLflow evaluation is a synchronous orchestration call that may invoke an async predictor; the wrapper is no longer incorrectly declared async.
* Delegated authority narrows purpose and cost as well as action, resource, data class, region, risk, time, and depth.
* Mutating tools require stable idempotency keys; ambiguous connector exceptions move effects to Unknown for reconciliation.
* Proposal-bound approval, CloudEvents/outbox, artifact-adoption policy, supply-chain attestation, kill-switch, and recovery-objective examples were added.
* Approval timestamps must be timezone-aware and causal; expiration is an exclusive boundary.
* Skill and Skill Pack versions use SemVer precedence; duplicate packs fail, and deprecated artifacts require explicit replay mode.
* ReAct stops repeated identical observations instead of looping to a turn limit.
* Compiled plans bind the plan to the policy envelope and make conservative cost-reservation semantics explicit.
* The direct OpenAI Responses adapter is contract-tested with a fake client, so the test proves request shape and platform-schema translation without a network call.
* The MLflow mortgage integration proves that `disable_openai_agent_tracer=False` exposes Agents SDK AgentRunner, agent, and tool spans while `trace_include_sensitive_data=False` keeps raw fixture content out of model trace payloads.
* The generated example report and CI output are authoritative for the test count.

## Authoring loop

The fast inner loop while writing:

```bash
$EDITOR source/parts/04-part-iv.md   # 1. edit canonical Markdown
make draft                           # 2. one XeLaTeX pass, seconds not minutes
                                     #    -> latex/build/*.pdf
```

`make draft` skips cross-reference convergence, so its page numbers and table of
contents are stale by design. Before sharing anything, run the real build:

```bash
make validate   # structure, citations, assets, contrast, determinism inputs
make pdf        # three-pass XeLaTeX -> dist/*-LaTeX.pdf
```

The rule the layout encodes: **everything above the blank line in `source/`,
`config/`, and `assets/` is hand-authored; everything in `book/`, `dist/`, and
`latex/content/` is generated and must never be hand-edited.** Presentation
changes belong in `latex/bookstyle.sty`, `config/book.json`, and `styles/` —
never in generated content.

## Safe edit workflow

1. Read `AGENTS.md`, `styles/DESIGN-SYSTEM.md`, and `styles/CROSS-FORMAT-CONTRACT.md`.
2. Create a working branch or copy of the repository.
3. Edit one or more canonical files under `source/parts/`.
4. If adding a cited claim, update `config/references.json`, allocate the next stable `Rxx`, and add `[Rxx]` at the sentence or paragraph that needs support.
5. If adding a diagram, add its source/export to `assets/diagrams/`, update `config/diagrams.json`, and place `[[DIAGRAM:id|caption]]` on its own line.
6. Run `make assemble`, review the Markdown diff, then run `make build latex` to regenerate DOCX and the LaTeX source.
7. Run `make validate`. Resolve all errors; do not suppress a check without recording the rationale.
8. Run `make pdf` and inspect the changed pages. For release candidates also run `make qa-pdf` and inspect the contact sheet and chapter-start report.
9. Update `CHANGELOG.md`, version metadata, and release notes.
10. Run `make package`, extract the ZIP into a clean folder, and run `make validate` there.
11. Only after the clean-package test passes, synchronize the approved manuscript and attachments to Notion.

## Editing topology

- `00-front-matter.md`: title marker, publication preface, reader map, table of contents.
- `01-part-i.md` … `08-part-viii.md`: one Part divider plus its chapters.
- `09-appendices.md`: appendix divider and Appendices A–L.
- Every Part, chapter, and appendix begins with an H1. DOCX rendering inserts a new page before each and makes Part/appendix dividers standalone.
- H2 is a major section, H3 a subsection, and H4 a local subtopic. Do not skip levels.
- Keep transitions at chapter endings so prerequisites and next steps remain explicit.

## References and claim discipline

`config/references.json` defines each source, version/date, URL, permitted support scope, verification date, and source class. Appendix K is generated from this registry during assembly. Cite only what the recorded scope supports. Book-authored patterns, estimates, examples, architectures, and formulas must be identified as guidance unless a reference explicitly validates them. Living documentation uses `n.d.` plus an access date. Maturity-sensitive claims must state pins and re-verification requirements rather than claiming a framework is “latest.”

Run:

```bash
python3 tools/check_references.py --root .
```

Online link checking is intentionally optional because reproducible offline builds must not depend on network access.

## Determinism

The assembler normalizes line endings. The DOCX builder fixes metadata, package timestamps, ZIP member order, styles, page geometry, and media insertion order. The packager fixes ZIP entry timestamps and ordering. A deterministic build check compiles DOCX twice in isolated output directories and compares SHA-256 hashes.

Expected differences are allowed only after canonical source, configuration, assets, dependencies, or build tools change. Record those changes in the changelog and release manifest.

## Notion synchronization

Notion is a published representation, not the build source. Publish only after local validation. The Notion release page must identify Book v1.0.0, author, release date, structure counts, citation count, checksums, QA status, and attach the exact ZIP/DOCX/Markdown/cover produced by this package. Preserve child-page blocks and permissions. If private source material would be copied to a broader destination, obtain confirmation first.

## Troubleshooting

- **DOCX differs after rebuild:** verify exact dependency versions, fonts, assets, and that no one edited generated files.
- **Citation missing/unknown:** run `check_references.py`; add the registry entry or remove the unsupported marker.
- **Diagram missing:** confirm the marker ID exists in `config/diagrams.json` and the registered file exists.
- **Unexpected pagination:** compare fonts and LibreOffice/Word versions; content and DOCX structure remain canonical even when renderer pagination differs slightly.
- **Assembler overwrote an edit:** edits belong in `source/parts`, not `book/manuscript.md` or `dist/`.
- **Need to alter layout:** change `config/book.json` and `build_book.py` for DOCX, or `latex/bookstyle.sty` for the PDF; update the design system, rebuild, and visually re-approve representative pages.
- **`xelatex: command not found`:** install a TeX distribution, then run `./tools/bootstrap_tex.sh`. On macOS, BasicTeX installs to `/Library/TeX/texbin`, which a non-login shell may not have on `PATH`.
- **`File 'tcolorbox.sty' not found` (or `tikzfill.image`, `pdfcol`, `needspace`, `lastpage`):** a minimal TeX distribution. Run `./tools/bootstrap_tex.sh`; it installs into your user tree without `sudo`.
- **CI says generated files are out of date:** you edited `source/parts/` without regenerating. Run `make build latex` and commit `book/manuscript.md`, `dist/*`, and `latex/content/book-content.tex`.
